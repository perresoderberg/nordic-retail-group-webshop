# ADR-001: Persistent varukorg med localStorage

* **Status:** Beslutad
* **Datum:** 2026-09-23
* **Deltagare:** Per Söderberg, Kinga Szayer
* **Relaterad Issue/Ticket:** #31

---

## 1. Kontext & Problemställning
*Vilken utmaning eller vilket behov står vi inför? Vilka krav och begränsningar styr oss?*

Vi vill implementera en persistent varukorg i webbshoppen så att kunden kan
lägga till produkter, ändra antal och ta bort produkter.
 
Varukorgens innehåll ska finnas kvar även om användaren laddar om sidan.
Vi behöver därför spara varukorgens data på ett sätt som är enkelt att
implementera och passar projektets omfattning.

---

## 2. Övervägda Alternativ

### Alternativ A: localStorage
 
- **Fördelar:** Inbyggt i webbläsaren, kräver inga externa paket och är enkelt
  att använda för att spara varukorgens innehåll mellan sidladdningar.
- **Nackdelar:** Datan sparas endast i användarens webbläsare och synkroniseras
  inte mellan olika enheter eller webbläsare.
 
### Alternativ B: Zustand med persist-middleware
 
- **Fördelar:** Ger centraliserad state-hantering och har stöd för att
  automatiskt spara state i localStorage.
- **Nackdelar:** Kräver ett extra npm-paket och innebär ytterligare teknik
  som teamet behöver sätta sig in i.
 
### Alternativ C: Cookies
 
- **Fördelar:** Kan användas för att spara information mellan sidladdningar
  och kan även göras tillgänglig på serversidan.
- **Nackdelar:** Mer komplex hantering än vad som behövs för vår varukorg
  och cookies har begränsat lagringsutrymme.
  
### Alternativ D: React Context
- **Fördelar:** Inbyggt i React och enkelt för att dela state mellan komponenter.
- **Nackdelar:** Kan bli svårhanterligt när state och logik växer.

---

## 3. Beslut
*Vilket alternativ valde vi och varför?*

Vi beslutar att använda localStorage för att spara varukorgens innehåll.
 
Vi valde localStorage eftersom lösningen är tillräcklig för projektets behov,
inte kräver några externa beroenden och är enkel för båda teammedlemmarna
att förstå och arbeta med.
 
Varukorgens innehåll kan därmed finnas kvar när användaren laddar om sidan.

---

## 4. Konsekvenser

### Positiva konsekvenser
 
- Varukorgens innehåll finns kvar efter sidomladdning.
- Lösningen kräver inga externa paket.
- Implementationen är relativt enkel.
- Båda teammedlemmarna kan förstå och underhålla lösningen.
 
### Negativa konsekvenser / Risker
 
- Varukorgen sparas endast lokalt i användarens webbläsare.
- Varukorgen synkroniseras inte mellan olika enheter eller webbläsare.
- localStorage är endast tillgängligt i webbläsaren och måste därför hanteras på klientsidan.
  
---
